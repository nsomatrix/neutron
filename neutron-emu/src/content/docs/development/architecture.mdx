## Architectural Philosophy

Neutron is designed around a decoupled, modular architecture that cleanly separates the emulated mobile Java runtime environment from desktop platform bridges and user interface presentations.

```
┌───────────────────────────────────────────────────────────┐
│               Desktop Presentation Layer                  │
│       FlatLaf Look & Feel / Menus / Virtual Keypad        │
├───────────────────────────────────────────────────────────┤
│                     Platform Bridge                       │
│      Display (xBRZ/Raster) │ Audio (MMAPI) │ GCF / Socket │
├───────────────────────────────────────────────────────────┤
│               Mobile Extensions Subsystem                 │
│  MascotCapsule Micro3D v3 │ JSR-184 M3G │ Nokia UI Direct │
├───────────────────────────────────────────────────────────┤
│                   J2ME Emulation Core                     │
│    CLDC 1.1 / MIDP 2.0 APIs │ LCDUI Controls │ RMS Engine │
├───────────────────────────────────────────────────────────┤
│              Bytecode Preprocessor & Loader               │
│        MIDletClassLoader / Method & Class Injection       │
└───────────────────────────────────────────────────────────┘
```

## Dual Distribution Architecture

Neutron is distributed in two optimized binaries sharing identical emulation engines:

```
                  ┌────────────────────────────────────────┐
                  │              neutron-core              │
                  │   CoreLauncher (XZ Decompressor Entry)  │
                  └───────────────────┬────────────────────┘
                                      │ Unpacks & Loads
                                      ▼
┌──────────────────────────────────────────────────────────┐
│                   neutron-javase-swing                   │
│        org.neutron.app.Main (Desktop Swing GUI)          │
└─────────────────────────────┬────────────────────────────┘
                              │
  ┌───────────────────────────┼───────────────────────────┐
  ▼                           ▼                           ▼
neutron-javase          neutron-midp                neutron-cldc
(Platform I/O)         (LCDUI & RMS)               (JVM APIs & GCF)
  │                           │                           │
  └───────────────────────────┼───────────────────────────┘
                              ▼
                     neutron-extensions
  (MascotCapsule 3D, JSR-184 M3G, Nokia UI, OEM APIs, AMMS)
```

1. **Neutron Express (`neutron-javase-swing`):**
   Full desktop application containing FlatLaf themes, Swing dialogs, Library Explorer, and runtime diagnostic overlays.
2. **Neutron Core (`neutron-core`):**
   Ultra-compact launcher that packages the entire emulator inside a high-ratio LZMA2/XZ compressed payload (`payload.jar.xz`). At runtime, `CoreLauncher` decompresses the payload into a temporary cache and boots seamlessly via reflection.

## Bytecode Classloading & Injection

MIDlets cannot invoke standard Java SE desktop APIs directly. Neutron employs a custom `MIDletClassLoader` that:
- Inspects JAR manifests (`MIDlet-1`, `MicroEdition-Profile`).
- Injects interception hooks for `System.getProperty("microedition.*")`.
- Intercepts thread execution and canvas repaints.
- Redirects I/O operations through the Generic Connection Framework (GCF).
- Delegates mobile extension packages (`com.mascotcapsule.*`, `com.nokia.mid.*`, `javax.microedition.m3g.*`) directly to the emulator's extension modules.

## Subsystem Details

### 1. LCDUI & Game Rendering
Canvas rendering dispatches through `SwingDisplayComponent`. The render loop buffers frame operations in volatile raster surfaces before applying selected shader filters (such as `xBRZ`, `Scale2x`, or CRT Scanlines) and presenting them onto the Swing Event Dispatch Thread (EDT).

### 2. Audio Processing (MMAPI)
Audio streams are routed to `SampledAudioPlayer` (WAV/AU), `AmrAudioPlayer` (AMR voice), or Java Sound's MIDI Sequencer. Playback controls support volume attenuation, thread-safe pause/resume, and seamless looping.

### 3. Record Management System (RMS)
Save files are persisted to disk using `FileRecordStoreManager`. Each MIDlet suite is assigned an isolated subfolder under `~/.neutron/suite-[MIDletName]/` containing discrete `.rms` record stores.
