## Community & Contributions

We welcome contributions of all forms — from bug reports and mobile game compatibility tests to 3D rasterizer optimizations and documentation improvements.

---

## Getting Started

1. Fork the official repository on GitHub: [https://github.com/nsomatrix/neutron](https://github.com/nsomatrix/neutron)
2. Clone your fork locally:
   ```bash
   git clone https://github.com/YOUR_USERNAME/neutron.git
   cd neutron
   ```
3. Create a descriptive feature branch:
   ```bash
   git checkout -b feature/my-new-feature
   ```
4. Build and verify the project:
   ```bash
   ./gradlew build
   ```

---

## Commit Guidelines

We use clear, conventional commit messages:

| Prefix | Focus Area |
|--------|------------|
| `feat:` | New feature, API extension, or UI capability |
| `fix:` | Bug fix, math correction, or spec compliance fix |
| `docs:` | Documentation website or markdown updates |
| `refactor:` | Code restructuring without behavior changes |
| `test:` | Adding unit tests or test MIDlets |
| `perf:` | Performance and memory optimizations |

---

## Coding Standards

- **Java Baseline:** Java 8 language compatibility (`sourceCompatibility = 1.8`, `targetCompatibility = 1.8`) to ensure lightweight portable execution.
- **Indentation:** Standard 4 spaces or tabs consistent with surrounding module files.
- **Spec Integrity:** Keep MIDP 2.0 and CLDC 1.1 spec methods compliant. If adding OEM extensions, provide clean fallbacks when device capabilities are absent.
- **Documentation:** When introducing new configuration parameters in `Config.java`, document them in `config2.xml` tables across the documentation pages.

---

## Submitting Pull Requests

1. Make sure all unit tests pass:
   ```bash
   ./gradlew test
   ```
2. If working on the web documentation site (`neutron-emu`):
   ```bash
   cd neutron-emu
   npm run build
   ```
3. Push your branch to GitHub and open a Pull Request against the `main` branch.
4. Describe your changes clearly, linking any relevant games or issues tested.
