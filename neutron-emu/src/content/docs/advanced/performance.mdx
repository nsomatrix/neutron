## Performance Overview

Neutron runs Java ME applications directly on top of modern Java SE Virtual Machines (JVM). Consequently, execution performance is native and benefits from the host JVM's highly optimized JIT compilers and garbage collection strategies.

However, you can configure several display and emulator parameters to optimize rendering speed and resource consumption.

## Emulator Options

These options are stored in the `config2.xml` under `<options>` and can be modified in the GUI settings:

### Frame Rate Limiting

Set a custom FPS limit to match a game's target speed and reduce CPU consumption:

```xml
<maxFps>60</maxFps> <!-- Options: -1 (unlimited), 60, 30, 20, 15 -->
```

<Callout type="tip">
Most classic J2ME games were designed for 30 FPS. Setting the limit to 30 can significantly reduce CPU and GPU usage on laptops.
</Callout>

### Thread Sleep Mode

Enable sleep mode to allow the emulation thread to sleep between loops, yielding CPU cycles back to the operating system:

```xml
<sleepMode>true</sleepMode>
```

## Memory Management

MIDlet applications run within the host JVM heap memory space. By default, the emulator limits internal J2ME heap allocation to **64 MB** to simulate original device constraints, but you can configure this to prevent out-of-memory errors in complex games.

### Setting Internal Memory Limits

Configure the virtual heap limit in `config2.xml`:

```xml
<memoryLimit>128</memoryLimit> <!-- Values: 32, 64, 128, 256, 512, 0 (unlimited) -->
```

### Configuring JRE Heap Size

For larger games or packages, increase the maximum memory pool allocated by the Java Virtual Machine using standard `-Xmx` JRE parameters:

```bash
# Run with 256MB of maximum JVM heap size
java -Xmx256m -jar neutron.jar game.jar
```

## Performance Tips

1. **Use Nearest Neighbor Filter** — This is the fastest scaling mode. Complex filters like CRT Scanlines or LCD Grid require additional CPU rendering cycles.
2. **Use the Latest JRE** — Running Neutron on newer runtimes (such as OpenJDK 17 or 21) provides updated garbage collection performance and execution optimization.
3. **Disable HUD Overlays** — Performance diagnostics (`<perfHudEnabled>`) and Network latency counters (`<networkOverlayEnabled>`) cause additional text rendering passes. Disable them if you require maximum frames-per-second.
