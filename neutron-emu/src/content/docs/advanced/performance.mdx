## Performance Overview

Because Neutron executes J2ME bytecode directly on the host Java Virtual Machine (JVM), there is no slow CPU interpretation cycle. MIDlet instructions benefit from the host JVM's advanced Just-In-Time (JIT) compiler (HotSpot / GraalVM) and generational garbage collectors.

However, fine-tuning display filters, memory constraints, and thread sleep settings allows you to maximize battery life on laptops or unlock maximum throughput for intensive 3D games.

---

## In-App Performance Controls

All performance parameters can be adjusted via the **Config** and **Controls** menus:

### 1. Frame Rate Limiting (`maxFps`)

Configure the target frame rate under **Controls → Frame Rate**:
- **Options:** `Unlimited (-1)`, `60 FPS`, `30 FPS`, `15 FPS`, or **Custom**.
- Setting an authentic 30 FPS cap cuts host CPU utilization by up to 50% while matching classic hardware timing.

### 2. Thread Sleep Mode (`Ctrl+L`)

Enable **Config → Sleep Mode** (or press `Ctrl+L`):
- Automatically injects micro-sleeps into the MIDlet render loop when no user input or frame changes are detected.
- Yields spare CPU cycles back to your operating system.

### 3. Emulated Memory Heap (`memoryLimit`)

Adjust under **Config → Memory Limit**:
- **Values:** `Unlimited (0)`, `32 MB`, `64 MB`, `128 MB`, `256 MB`, `512 MB`.
- Standard J2ME devices originally possessed between 2 MB and 16 MB of heap. Setting the limit to **64 MB or 128 MB** ensures maximum compatibility while preventing memory leaks from runaway MIDlets.

### 4. Performance HUD (Stats Overlay)

Enable **Controls → Stats Overlay** to monitor real-time metrics directly on top of the game screen:
- **Live FPS:** Dynamically sampled frame rate.
- **Frame Timing:** Latency per frame in milliseconds.
- **Memory Consumption:** Used heap memory versus total allocated JVM memory.

## Host JVM Tuning

You can pass JVM flags to Java when executing the Neutron JAR:

### Maximum Throughput (Modern JDK 17 / 21)
```bash
java -server -XX:+UseG1GC -Xmx512m -jar neutron-1.4.0.jar game.jar
```

### Low-Memory Footprint (Neutron Core)
```bash
java -XX:+UseSerialGC -XX:TieredStopAtLevel=1 -Xms16m -Xmx64m -jar neutron-core-1.4.0.jar game.jar
```

### Marlin 2D Vector Rendering
Neutron automatically leverages the high-speed Marlin Java2D renderer:
```bash
java -Dsun.java2d.renderer=sun.java2d.marlin.MarlinRenderingEngine -jar neutron-1.4.0.jar
```

## Filter Performance Guidelines

- **Fastest (Lowest CPU):** **Nearest Neighbor** performs simple point sampling with zero interpolation math.
- **High Quality (Recommended):** **xBRZ 2x** and **Scale2x** provide excellent edge smoothing with minimal CPU overhead.
- **Higher Scaling (xBRZ 4x–6x):** Best suited for desktop systems running on multi-core CPUs.
- **CRT / LCD Shaders:** CRT Scanlines and LCD Grid apply per-pixel raster masks. They look best on display scales of 2x or higher.
